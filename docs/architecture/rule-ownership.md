Resolved contradictions: ordinary questions do not start the delivery pipeline;
shared policy no longer relies on a particular user's global configuration;
PLAN facts must be updated rather than frozen for caching; capture is never
implicitly enabled; candidate notes are not adopted lessons; repeated corrections
do not silently edit root instructions; every customized existing file is
preserved, including oversized entries, until reviewed migration.

The source roots are generated by scripts/render_entries.py. Detailed policies
have one authored home; versioned installation snapshots are release artifacts,
not additional independently authored policy. Markdown links are on-demand routes.
The entry validator rejects eager @imports rather than hiding a handbook behind
an apparently compact root. No host config, rules directory, or memory setting
is installed implicitly. Pre-existing client configuration can load additional
instructions and must be inspected separately during optimization.

Versioned snapshot root/skill candidates use a .candidate suffix to avoid nested
client discovery while examining release policy. They are proposed inputs only.
